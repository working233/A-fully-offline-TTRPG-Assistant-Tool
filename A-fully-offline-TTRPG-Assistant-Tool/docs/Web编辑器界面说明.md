# Web 编辑器：界面布局与交互逻辑

> 打开方式：`python -m app.main` → 终端打印地址 → 浏览器自动打开
> 布局：左侧固定导航（232px）+ 右侧内容区（顶部标题栏 + 可滚动主体），浅色主题。

## 1. 全局框架

```
┌───────────────┬────────────────────────────────────────────────────────┐
│ 品牌区        │ 顶栏：当前视图标题 + 副标题            [ 操作按钮区 ]    │
│ [跑团下拉框]  ├────────────────────────────────────────────────────────┤
│               │                                                        │
│ ▸ 跑团管理    │                  内容区（各视图）                        │
│ ▸ 角色卡      │                                                        │
│ ▸ 怪物卡      │                                                        │
│ ▸ 骰子系统    │                                                        │
│ ▸ 剧情编辑器  │                                                        │
│ ▸ 文件与笔记  │                                                        │
│ ▸ 跑团记录    │                                                        │
│ ▸ 回收站/备份 │                                                        │
│               │                                                        │
│ ● 本地服务运行中                                                        │
└───────────────┴────────────────────────────────────────────────────────┘
```

- **跑团下拉框**：切换即 `POST /api/campaigns/{id}/activate`，之后所有列表请求自动带上 `campaign` 参数。
- **状态灯**：每 5 秒心跳一次；服务断开时变红并显示「本地服务已停止」（正常情况是关闭浏览器后进入该状态）。
- **Toast**：右下角浮层，成功绿 / 失败红，2.6s 自动消失。
- **统一错误出口**：任何接口返回 `ok:false` 都由 `api.js` 抛异常，由各视图 catch 后走 Toast。

## 2. 各视图

### 2.1 跑团管理
- 左侧「新建跑团」表单：名称 / 规则下拉 / DM / 简介 → 创建后自动切换并生成七个子目录。
- 右侧卡片列表：名称、规则、DM、创建时间与**资源计数**（角色 / 怪物 / 剧情 / 地图 / 笔记 / 日志行数）。
- 卡片操作：`切换`（仅非当前项显示）、`备份`、`删除`（二次确认 → 回收站）。

### 2.2 角色卡 / 怪物卡
- 左：可滚动列表，每张卡展示关键摘要（等级/职业/HP/AC 或 CR/类型/HP/AC）。
- 右：**Schema 驱动的动态表单**——字段定义来自 `GET /api/schemas/{kind}`（`app/core/validate.py`），
  支持 string / number / textarea / enum / list / list(object) / map / group 八种类型。
  - `map`（属性、技能）：textarea，每行 `键: 值`
  - `list`（装备、特性）：textarea，每行一项
  - `list(object)`（攻击动作）：JSON 文本域
- 顶部工具栏：`查看 JSON`（表单 ⇄ 原生 JSON 双向切换）、`复制`、`删除`、`保存`、`HP 快捷 ±1/±5`。
- 保存即调用服务端校验，错误信息显示在卡片底部红色提示行（字段缺失会以 `校验失败：缺少必填字段…` 形式回显）。

### 2.3 骰子系统
- 快捷区：`d4 d6 d8 d10 d12 d20 d100` 七个大按钮 + 数量 / 调整值 / 优劣势 / 标签；
  点击面数按钮会按当前设置拼出表达式并立即投掷。
- 表达式输入框：支持 `2d6+3`、`4d6kh3`、`d20 adv`、`3d10-1d4+2`；回车即投。
- 实时提示：`输入表达式时显示解析后的期望值`（调用 `/api/dice/expected`）。
- 结果卡：巨大数字（暴击变红）、每个骰组的原始点数（`dropped` 项灰色删除线）、小计、调整值、期望值、时间戳。
- `成功率` 按钮：弹窗输入 DC → `GET /api/dice/probability` 返回精确百分比（DP 卷积解）。
- 右栏历史：倒序列出全部投掷，每条带「复用」按钮回填表达式；可一键清空。

### 2.4 剧情编辑器（核心）
- 顶部工具条：剧情下拉 / 新建 / **图谱校验** / **自动布局** / **导出 DOT**。
- 中部左侧 **剧情图画布**：
  - 节点按 `main/branch/ending` 用蓝/紫/红左边框区分，显示标题、正文摘要、分支数量徽标。
  - 连线：实线 = `next` 直连（蓝），虚线 = 分支跳转（紫），弧线为贝塞尔曲线并标注选项文案。
  - **拖拽**：`mousedown` 进入拖动模式，鼠标移动实时跟随；`mouseup` 落点取整后
    `PUT /api/stories/{slug}/nodes/{id} {position}`，无需点保存。
  - **点击节点** → 右侧编辑面板。
- 中部右侧 **节点编辑面板**：标题、类型（主线/分支/结局）、结局类型、正文、标签、直连下一节点下拉、
  分支列表（每项：文案 / 跳转目标 / 条件 JSON / 效果 JSON，带提示示例）、`+ 新增分支`、`保存节点`、`删除节点`。
  - 删除节点会**自动把父节点的连线接到它的后继**（`relink=True`），不会把图谱拆成孤岛。
- 底部抽屉 **Graphviz DOT**：`复制` / `下载 .dot`，提示 `dot -Tsvg story.dot -o story.svg`。
- 校验结果：绿色「校验通过」或红色错误清单 + 琥珀色提示（不可达节点、死路）。

### 2.5 文件与笔记
- 左：目录树（`depth=4`），图标区分目录 / 文本 / 图片 / 二进制，显示 KB 体积；`新建文件` / `刷新`。
- 右：纯文本编辑器，`Ctrl+S` 保存（PUT `/api/files`，服务端原子写），`删除` 进回收站（二次确认）。
- 图片类资源（`maps/*.png`）在树中标记但不在文本编辑器打开，等待地图查看器渲染（见路线图 P0）。

### 2.6 跑团记录
- 左：日志输入区（类型下拉 / 当事人 / 标签 / 正文）→ 写入，下方为**倒序时间线**（类型徽标 + 当事人 + 正文 + 时间戳 + 标签）。
- 右：
  - 花名册表格 + 快速添加（玩家 / 角色 / 联系方式），行内移除。
  - LOOT 台账：物品 / 数量 / 价值 / 持有者 / 状态，行内删除。
  - 导出：点击「生成 Markdown」→ `GET /api/records/export?format=md`，结果填入文本框可手动复制。

### 2.7 回收站 / 备份
- 回收站列表：类型徽标、原始路径、删除时间、体积；每行 `还原` / `彻底删除`（二次确认）；右上角 `清空回收站`。
- 备份列表：文件名、范围（campaign/all）、体积、`还原`；顶部 `备份当前跑团` / `全量备份`。
- 底部给出迁移提示：数据目录或 zip 直接拷到另一台机器即可恢复。

## 3. 交互逻辑要点

1. **乐观 UI + 服务端兜底**：所有写操作先请求，成功后 Toast 并局部刷新；失败只提示不丢已经输入的内容（表单不清空）。
2. **破坏性操作必有确认**：删除实体 / 删除跑团 / 清空回收站 / 彻底删除均走 `confirm()`。
3. **实时保存的两种形态**：文件编辑用 `Ctrl+S`；剧情节点拖拽用「松手即保存」；卡片编辑用显式按钮（避免半填状态的脏写）。
4. **心跳与自动停止**：前端每 5s `POST /api/ping`；浏览器关闭后，服务端 watchdog 在 ~25s 无心跳时自动 `shutdown()`，
   进程干净退出，**不留后台常驻、不占端口**。
5. **零外部资源**：页面不加载任何 CDN 资源，离线可直接打开；所有依赖为本地 `css/app.css` 与三个 `js` 文件。
