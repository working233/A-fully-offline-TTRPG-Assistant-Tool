# 本地跑团辅助工具 · 技术方案

> 版本 v0.1.0 ｜ 目标：完全离线、数据自持、可扩展规则（COC 7th / DND 5e / 自定义）
> 所有数据落在本机目录树中，不依赖任何云端服务、不需要数据库服务进程。

---

## 1. 架构总览（分层，业务逻辑与 UI 完全解耦）

```
┌────────────────────────────────────────────────────────────────────────┐
│  表现层 Presentation                                                    │
│  ├─ Web 编辑器（推荐）  HTML5 + 原生 JS，通过本地 HTTP 服务访问          │
│  ├─ 桌面编辑器（可选）  Python Tkinter，复用同一套 Service API           │
│  └─ CLI                python -m app.main --doctor / --backup / --seed  │
└───────────────────────────────┬────────────────────────────────────────┘
                                │  唯一契约：JSON over HTTP / REST
                                │  GET|POST|PUT|PATCH|DELETE /api/...
┌───────────────────────────────▼────────────────────────────────────────┐
│  传输层 Transport        app/api.py（ApiRouter，与传输方式无关）         │
│                         app/server.py（回环绑定 / 自动端口 / 心跳停止）  │
│                         统一返回 {ok,data} | {ok:false,error{code,...}} │
└───────────────────────────────┬────────────────────────────────────────┘
┌───────────────────────────────▼────────────────────────────────────────┐
│  服务层 Services（禁止引用任何 UI 代码，可独立单测 / 可被 Tk 复用）      │
│  CampaignService   跑团生命周期、目录骨架、导入导出                     │
│  FileManagerService文件树、读写、重命名、移动、搜索、资源导入            │
│  TrashService      隐藏删除（移动进回收站）/ 还原 / 彻底删除 / 过期清理  │
│  DiceService       表达式解析、投掷、期望值、精确概率、历史与统计        │
│  EntityService     人物卡 / 怪物卡 模板、校验、CRUD、快捷 HP 调整        │
│  StoryService      剧情图谱 CRUD、可达性校验、BFS 分层布局、DOT 导出     │
│  RecordService     时间线日志（jsonl）、花名册、LOOT 台账、Markdown 导出 │
│  BackupService     zip 快照 + 轮转保留 + 还原                           │
└───────────────────────────────┬────────────────────────────────────────┘
┌───────────────────────────────▼────────────────────────────────────────┐
│  内核层 core（纯函数 / 原子 IO / 不依赖上层）                            │
│  paths.py 目录根系   jsonio.py 原子写 jsonl   validate.py schema 校验    │
│  safety.py 路径越界守卫   errors.py 统一异常   events.py 事件总线        │
└───────────────────────────────┬────────────────────────────────────────┘
┌───────────────────────────────▼────────────────────────────────────────┐
│  存储层 Storage                                                         │
│  JSON 文件（主）+ JSONL 追加日志 + zip 快照备份 + SQLite（可选插件）      │
└────────────────────────────────────────────────────────────────────────┘

依赖方向严格单向向下：Presentation → Services → core → Storage
反向通信一律通过 EventBus 事件（如 `campaign/created`、`file/written`）实现。
```

### 1.1 为什么是「JSON 文件优先」而不是 SQLite

| 维度 | JSON 文件（本方案） | SQLite |
|---|---|---|
| 可读性/可版本管理 | 人眼可读，可 git diff、可手动改 | 需工具查看 |
| 迁移与备份 | 直接复制文件夹，零导出成本 | 需导出或直接拷 .db |
| 单文件即是完整实体 | 一张卡 = 一个文件，冲突面极小 | 行级锁、schema 迁移成本 |
| 适合的规模 | 几十个跑团、单团几千条目（绰绰有余） | 十万级以上、复杂关联查询 |

折中：**结构化实体用 JSON，会话日志用 JSONL（追加写、抗损坏）**。若未来需要「跨跑团全文检索 / 大量时间线聚合」，再引入 SQLite 作为只读索引插件——届时只需新增 `IndexService`，上层不受影响。

## 2. 技术选型

| 领域 | 选择 | 理由 |
|---|---|---|
| 语言 | Python 3.11+（仅标准库） | 零安装依赖，`python -m app.main` 直接跑；升级不会炸 |
| HTTP | `http.server.ThreadingHTTPServer` | 自带、够用；单用户本地场景无需 ASGI |
| 前端 | 原生 HTML + CSS + JS（无构建） | 无 npm/打包链路，离线可用；改一个文件即时生效 |
| 图表/流程可视化 | SVG 手绘 + Graphviz DOT 导出 | 编辑器内拖拽用 SVG；出图用 `dot -Tsvg` |
| 数据存储 | JSON / JSONL / zip | 见 1.1 |
| 桌面 UI（可选） | Tkinter | 标准库自带，直接复用 Service 层，无需重写逻辑 |
| 测试 | 标准库 unittest | 零依赖，Service 层纯函数化后极易覆盖 |

**约束**：不引入 FastAPI / Django / requests / jsonschema 等第三方包。整个仓库 `pip install` 依赖数为 0。

## 4. 数据模型

### 4.1 人物卡（`characters/*.json`）

字段：姓名 `name`、玩家 `player`、种族 `race`、职业 `klass`、等级 `level`、
生命值 `hp{current,max,temp}`、护甲等级 `ac`、速度 `speed`、
属性 `attributes{}`、技能 `skills{}`、豁免 `saves{}`、装备 `equipment[]`、
特性/法术 `features[]`、背景 `background`、备注 `notes`、立绘 `portrait`。

规则差异体现在字段取值上而非结构上（同一套结构既能装 DND，也能装 COC）：

| 规则 | attributes | skills | 附加字段 |
|---|---|---|---|
| DND 5e | STR/DEX/CON/INT/WIS/CHA = 10 | 加值型（洞察 +4） | `proficiency`、`hit_dice`、`saves` |
| COC 7th | STR/CON/SIZ/DEX/APP/INT/POW/EDU = 50 | 百分比型（侦查 60） | `derived{SAN,LUCK,MP,MOV,DB,BUILD}` |

示例见 `samples/demo-campaign/hollow-lighthouse/characters/valen-thorne.json`（DND 5e）
与 `eleanor-hallow.json`（COC 7th）。

### 4.2 怪物卡（`monsters/*.json`）

字段：名称 `name`、类型/体型 `type`、阵营 `alignment`、挑战等级 `cr`、
`hp{current,max}`、`ac`、速度 `speed`、属性 `attributes`、技能/豁免 `skills`、
抗性 `resistances[]`、免疫 `immunities[]`、易伤 `vulnerabilities[]`、
攻击 `attacks[{name,attack,damage,type,note}]`、特殊能力 `abilities[]`、
描述 `description`、掉落 `loot[]`。

### 4.3 剧情 JSON（`stories/*.json`）

```jsonc
{
  "id": "st-xxx", "title": "空心灯塔", "system": "COC 7th",
  "start_node": "arrive",
  "flags": { "has_brass_key": false, "knows_lullaby": false },  // 初始剧情标记
  "nodes": [
    {
      "id": "investigation_hub",
      "type": "main | branch | ending",        // 主线 / 分支 / 结局
      "ending_type": "good|bad|neutral|open",   // type=ending 时必填
      "title": "三条线索",
      "text": "天还没全黑，你有大约两小时……",
      "tags": ["调查"],
      "effects": [{"type": "flag", "flag": "x", "value": true},
                  {"type": "san", "value": "1/1d6"}],
      "next": "top_floor",                     // 单出口直连
      "choices": [                             // 分支出口
        { "id": "c1", "label": "唱出摇篮曲", "target": "ending_extinguish",
          "condition": {"type": "flag",  "flag": "knows_lullaby", "equals": true},
          "effects":   [{"type": "flag", "flag": "sang", "value": true}] }
      ],
      "position": {"x": 620, "y": 200}         // 编辑器拖拽坐标，可选
    }
  ]
}
```

**条件类型（condition）**

| type | 语义 | 示例 |
|---|---|---|
| `flag` | 剧情标记判定 | `{"type":"flag","flag":"has_brass_key","equals":true}` |
| `skill` | 技能检定通过才显示/可选 | `{"type":"skill","skill":"侦查","difficulty":"hard"}` |
| `expr` | 任意表达式（带白名单求值） | `{"type":"expr","expr":"SAN >= 50"}` |

`StoryService.validate_graph()` 会检查：id 唯一、目标存在、起始节点存在、
并给出「不可达节点」「死路（非结局且无后继）」告警；
`walk()` 可带一组 flags 模拟推进剧情，用于排练和条件分支自测。

### 4.4 地图配置（`maps/<name>.map.json`）

`grid{mode: square|hex, cell_size, columns, rows}`、`lighting{sources[{x,y,radius,color,type,flicker}]}`、
`fog{enabled, revealed[[x,y]...], mode}`、`tokens[{name,x,y,hidden,ref}]`。
图片本体是同目录下的同名图片，删除/替换图片不影响配置。

## 5. 内置智能本地服务器

```text
app/server.py :: LocalServer
├── pick_port()      偏好端口 8765~8804 依次探测，全被占用则由内核分配空闲端口
├── 绑定 127.0.0.1    仅本机回环，局域网/WiFi 同网段设备无法访问（隐私默认最优）
├── 同端口静态资源     "/" → web/index.html，避免 CORS 与跨端口凭证问题
├── 心跳看门狗        前端每 5s POST /api/ping；watchdog 线程每 2s 检查空闲时长
│                    超时默认 25s → 自动 shutdown + server_close，进程退出，不留常驻
├── ThreadingHTTPServer + daemon_threads：Ctrl+C 或超时均可干净退出
└── 所有请求先 touch() 更新活跃时间；日志静默，不刷屏
```

启动即打印访问地址、数据目录、回环提示，并自动打开默认浏览器（`--no-open` 可关闭）。

## 6. API 契约（节选）

统一结构：`{"ok":true,"data":...}` / `{"ok":false,"error":{"code","message","details"}}`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/campaigns` | 列表 / 创建 |
| GET/PATCH/DELETE | `/api/campaigns/{id}` | 详情 / 更新 / 删除（进回收站） |
| POST | `/api/campaigns/{id}/activate` | 切换当前跑团 |
| GET | `/api/campaigns/{id}/tree` | 目录树 |
| GET/PUT | `/api/files?path=`、`/api/files/content` | 文件树 / 读写 |
| POST | `/api/files/import` | 导入地图图片（base64 或本机路径） |
| GET/POST/DELETE | `/api/trash`、`/api/trash/restore` | 回收站列表 / 还原 / 彻底删除 |
| GET/POST/PUT/DELETE | `/api/characters`、`/api/monsters` | 卡片 CRUD |
| POST | `/api/{kind}/{slug}/hp` | HP 快捷调整 `{"delta":-6}` |
| GET | `/api/templates/{character,monster}?system=` | 规则化模板 |
| GET | `/api/schemas/{character,monster,story}` | Schema（前端据此动态生成表单） |
| GET/PUT | `/api/stories/{slug}` | 剧情读写 |
| POST/PUT/DELETE | `/api/stories/{slug}/nodes[/{nodeId}]` | 节点增删改（删除自动重连） |
| GET | `/api/stories/{slug}/{validate,layout,dot}` | 校验 / 自动布局 / DOT 导出 |
| POST | `/api/dice/roll` | 投掷 `{expression,advantage,seed,label}` |
| GET | `/api/dice/{history,expected,probability,stats}` | 历史 / 期望值 / 精确概率 / 统计 |
| GET/POST | `/api/records/{logs,party,loot}` | 日志 / 花名册 / 战利品 |
| GET | `/api/records/export?format=md` | Markdown 导出 |
| GET/POST | `/api/backups`、`/api/backups/restore` | 备份 / 还原 |

所有 `ServiceError` 自动映射 HTTP 状态：`not_found 404 / validation_failed 422 / safety_violation 403 / conflict 409`。

## 7. 安全与可靠性设计

| 机制 | 实现 |
|---|---|
| 路径越界防护 | 所有文件 IO 先过 `core/safety.ensure_inside()`，`../..` 直接 403。冒烟测试已验证 |
| 隐藏删除 | 一切删除 = `shutil.move` 到 `_trash/<token>/` + 写 `.meta.json`（原始路径、跑团、时间、大小），可一键还原到原路径 |
| 回收站过期清理 | `TrashService.auto_cleanup(keep_days=30)` 可定期清理，避免无限膨胀 |
| 写入原子性 | `jsonio.write_json`：临时文件 → fsync → `os.replace`，断电/崩溃不留半截 JSON |
| 日志抗损坏 | JSONL 一行一条，坏行跳过解析，不影响整体加载 |
| 破坏操作确认 | 前端所有删除/清空均 `confirm()`；只有回收站「还原」无需确认 |
| 可撤销 | ① 回收站还原 ② 剧情删除节点自动重接父连线（`relink=True`）③ 剧情每次保存 `version+1` ④ 备份 zip 兜底 |
| 备份与迁移 | 单跑团 / 全量 zip 快照，轮转保留 10 份；把数据目录或 zip 拷走即可跨设备恢复 |
| 隐私 | 仅监听 127.0.0.1、无遥测、无外发请求、无云同步；`Cache-Control: no-store` |

## 9. 扩展思考

### 9.1 多人联机实时同步

数据模型已经幂等（每个实体一个文件 + 独立 id），加同步只需在 Service 层叠一层：

1. **CRDT/OT 太重，够用的方案是「操作日志 + 最后一写获胜 + 冲突快照」**：
   `TrashService.move_to_trash` 已保留原对象，天然产生冲突备份；
   冲突时把远端版本写入 `<file>.conflict-<peer>.json`，由 DM 人工合并。
2. **传输**：本机 ServiceRegistry 之上加一个 `SyncService`，用 WebSocket（`websockets` 是唯一需要装的包）广播
   `{entity_key, version, payload_hash, author}`；同 key 比较 `updated_at` + `version`。
3. **权限分层**：DM 可写 `stories/`、`monsters/`，玩家只能写自己的 `characters/<id>.json` 与 `handouts/`；
   服务端对每个 diff 做白名单校验。
4. **离线优先**：玩家断网期间写入本地 diff 队列，重连后重放；由于 entity 粒度小，冲突概率极低。

### 9.2 剧情可视化生成（JSON → DOT → SVG）

链路已经打通一半：

```
stories/x.json --StoryService.to_dot()--> story.dot --graphviz--> story.svg --浏览器/文档--> PNG
                        │
                        └--StoryService.layout()--> BFS 分层坐标 --> Web 编辑器内 SVG 直接拖拽
```

落地步骤：

1. `GET /api/stories/{slug}/dot` 已在 API 层可用，前端有「导出 DOT / 复制 / 下载」按钮。
2. 安装 Graphviz（`winget install graphviz`），命令行 `dot -Tsvg story.dot -o story.svg`。
3. 想在应用内一键出图：在 `StoryService` 增加 `to_svg()`，通过 `subprocess.run(["dot","-Tsvg"], input=dot)`
   调用本地 Graphviz；检测不到 graphviz 时降级为「编辑器内置 SVG 渲染」（已实现），保证功能不缺。
4. 进一步优化：把 layout 换成 Sugiyama 分层（长边→虚拟节点、重心排序减少交叉），或直接用
   `dagre`/`elkjs` 的 wasm 版本在前端排布，避免依赖外部二进制。

### 9.3 AI 辅助生成（剧情 / 角色卡 / 怪物数据）

通过对外的本地守护进程做「可选增强」，不污染核心：

1. **本地优先**：把 AI 服务做成 `AiService`，默认实现是「模板 + 掷表」的本地生成器（已有 scaffolding 思路：
   `EntityService.template()` 就是种子数据），可选实现调用本机 Ollama / LM Studio 的 OpenAI 兼容接口
   `http://127.0.0.1:11434`，数据仍然不离开本机（离线即可用）。
2. **Prompt 契约**：让模型输出的不是自由文本，而是**严格 JSON Schema**（可用 `/api/schemas/{kind}` 返回的同一份描述生成 prompt），
   输出后立刻走 `validate_document()`；校验失败自动重试 1 次并把错误信息回灌给模型（self-correction loop）。
3. **剧情生成**：先让模型输出 `nodes[]` 摘要，再由 `StoryService.add_node(attach_to=...)` 逐个挂载，
   这样每一步都在图谱约束内；生成结束跑一次 `validate_graph()`，把「不可达 / 死路」作为二次润色的输入。
4. **可解释性**：AI 生成的每条字段都写入 `provenance` 备注（例如 `"by": "ai", "model": "qwen2.5:14b"`），
   DM 一眼可辨哪些是人写的、哪些是 AI 写的，方便审核。

### 9.4 自定义规则模板

1. **零改代码扩展**：`core/validate.py` 的 `RULE_SYSTEMS` 是纯数据，`system` 字段可以自由取值；
   只要把新规则追加进去，`/api/templates/{kind}?system=xxx` 即可返回对应种子卡。
2. **模板文件化（推荐下一步）**：把 `CHARACTER_SCHEMA` / `MONSTER_SCHEMA` 外置成
   `templates/<rule>.{character,monster}.schema.json`，`EntityService.schema(rule)` 按规则名懒加载；
   因为前端表单是由 Schema 动态渲染的（`views.js :: buildField()`），新增字段后 UI 自动长出对应输入框。
3. **派生属性公式**：在模板里加 `derived_rules`，如
   `{"hp_max": "CON_mod + klass_base", "initiative": "DEX_mod"}`，用受限表达式求值器（复用 `condition.expr` 的白名单求值）
   计算，支持「每回合自动重算」的小众规则。
4. **兼容性**：老文件缺字段不报错——校验只 check `required` 三项（`id/system/name`），
   新增字段对存量数据一律容错，避免规则升级导致旧卡打不开。
